# Phase 04 — Approval Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Approval service gives humans a durable escalation queue: it consumes `decision-made` (route `human_review`), persists escalation records + a queue index (the pause **is** a record — nothing waits in memory), serves the approver queue with the agent's rationale (F4), applies exactly-once verdicts (approve/reject/send-back, F5), publishes `approval-resolved`, and provably survives a service restart between pause and resume (M11) — demonstrated in the compose smoke by restarting the container mid-journey.

**Architecture:** Spec §5, decisions D-013 (pause = durable record; CAS-guarded verdict), D-015 (own keys: `escalation:*`, `queue:pending`, `processed:*`), D-016 (afcommon EventDedupe). Service pattern copied from decision-svc (relative imports inside `src/` — CI guard enforces).

**Tech Stack:** Python 3.12 · FastAPI · pydantic v2 · afcommon (state/CAS, dedupe, contracts, logging) · Dapr pub/sub + state · Redis.

## Global Constraints

- The pause is a state record: NO timers, NO background workers, NO in-memory queues anywhere in this service (D-013 — this absence is the M11 mechanism; reviewers should flag any such construct as a defect).
- Verdict idempotency (M10 for humans): apply only while `status == "pending"` via CAS transform — double-clicks, retries, and racing approvers produce exactly one effect; losers get `409`.
- Queue index updates via `cas_update` (concurrent escalations/resolutions never lose entries).
- Consumer dedupe via afcommon `EventDedupe` with the decision-svc pattern: mark → process → `forget` on failure → re-raise 500.
- Money display comes from the event's `usd_cents`; this service never recomputes amounts.
- Branch `feature/approval` off `main`; conventional commits; controller pushes per task; PR at the end. Baseline: **203 passed**.
- Installed-package imports; relative imports inside `src/`; no noqa.

### Task 3: Approver API — queue view + exactly-once verdicts

**Files:**
- Create: `services/approval/src/api.py`; Modify: `main.py`
- Test: `services/approval/tests/test_api.py`

**Interfaces:**
- `GET /api/approvals/queue` → `{"items": [...]}` — full escalation view for each pending id (F4: recommendation, confidence, violations, reasoning, usd_cents, timestamps), oldest first (sort by `escalated_at`). Ids in the index whose record is missing/non-pending are skipped AND lazily removed from the index (self-healing; log warning).
- `POST /api/approvals/{invoice_id}/verdict` body `{"verdict": "approved"|"rejected"|"needs_info", "approver_id": str (required, non-empty), "comment": str = ""}`:
  - 404 unknown escalation · 422 invalid body/verdict (pydantic Literal).
  - CAS transform: if `status != pending` → the transform raises `AlreadyResolved` (custom exc) → **409** with the existing resolution in the body (who/when/what — idempotent-read-back, kinder than bare conflict).
  - On success: status ← verdict, `resolved_by/resolved_at/resolution_comment` set → remove_from_queue → publish `ApprovalResolvedPayload(meta=new_event_meta(invoice_id, correlation_id), verdict, approver_id, comment)` → 200 with the updated view.
  - **Publish failure policy (F5-critical, mirror intake's fail-loud M15):** if publish raises AFTER the CAS resolution committed, roll BACK the resolution via a compensating CAS (status → pending, resolved_* cleared, re-add to queue), return **503 "verdict accepted but could not be delivered; retry"**. Tests must cover: rollback leaves the record re-approvable, and the queue re-contains the id. (Do NOT leave a resolved-but-unpublished record — that invoice would hang forever, the exact failure M11 exists to prevent.)
- DI seams: `get_repo`, `get_publisher` (same pattern as intake).

- [ ] **Step 1: Failing tests:** queue empty → `{"items": []}` · escalate two (via repo direct or subscriber) → queue ordered oldest-first with full F4 fields · verdict approved → 200, record resolved, queue empty, `approval-resolved` published with same correlation_id + fresh event_id · double-POST same verdict → second gets 409 WITH resolution details · needs_info and rejected variants → correct payload verdict · missing approver_id → 422 · unknown id → 404 · concurrent racing verdicts (two tasks, YieldingStateStore) → exactly one 200, one 409 · **publish-failure rollback: flaky publisher raising → 503, record back to pending, id back in queue; retry succeeds → 200 and exactly one publish.**

```bash
echo "--- approval E2E: escalate -> RESTART -> resume (M11 / journey B) ---"
ESC_PAYLOAD=$(python3 - <<'EOF'
import json
data = json.load(open("sample-invoices.json"))
inv = next(f for f in data["fixtures"] if f["id"] == "INV-1003")
inv = {k: v for k, v in inv.items() if k not in ("expected", "scenario")}
print(json.dumps(inv))
EOF
)
TRACK3=$(curl -sf -X POST http://localhost:8001/api/invoices -H 'Content-Type: application/json' \
  -d "$ESC_PAYLOAD" | python3 -c "import sys,json; print(json.load(sys.stdin)['trackingId'])")
for i in $(seq 1 30); do
  S3=$(curl -sf "http://localhost:8001/api/invoices/$TRACK3" | python3 -c "import sys,json; print(json.load(sys.stdin)['status'])")
  [ "$S3" = "pending_approval" ] && break; sleep 1
done
[ "$S3" = "pending_approval" ] || { echo "FAIL: expected pending_approval, got $S3"; exit 1; }
curl -sf http://localhost:8003/api/approvals/queue | grep -q "$TRACK3" || { echo "FAIL: not in queue"; exit 1; }

echo "--- restarting approval-svc (the M11 moment) ---"
docker compose restart approval-svc approval-svc-dapr
for i in $(seq 1 30); do
  curl -sf http://localhost:8003/healthz >/dev/null 2>&1 && break; sleep 1
done
curl -sf http://localhost:8003/api/approvals/queue | grep -q "$TRACK3" \
  || { echo "FAIL: queue lost across restart — M11 broken"; exit 1; }

curl -sf -X POST "http://localhost:8003/api/approvals/$TRACK3/verdict" \
  -H 'Content-Type: application/json' \
  -d '{"verdict":"approved","approver_id":"lena.schmidt@northwind.example","comment":"client name confirmed offline"}' >/dev/null \
  || { echo "FAIL: verdict rejected"; exit 1; }
for i in $(seq 1 30); do
  S3=$(curl -sf "http://localhost:8001/api/invoices/$TRACK3" | python3 -c "import sys,json; print(json.load(sys.stdin)['status'])")
  [ "$S3" = "approved" ] && break; sleep 1
done
[ "$S3" = "approved" ] || { echo "FAIL: resume did not reach intake, got $S3"; exit 1; }
echo "APPROVAL E2E (M11 restart survived): OK"
```
