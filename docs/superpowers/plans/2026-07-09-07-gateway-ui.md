# Phase 07 — Gateway + UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The last two must-haves. An **nginx gateway** (M6) is the single external entry point on port 8080: it routes `/api/*` to the six services, rate-limits every client, and serves the built UI's static files. A **minimal React SPA** (M7) drives the whole system: submit an invoice and watch its status/decision, work the approver queue (F4/F5), see the dashboard (F8), tune thresholds (F7), and view any invoice's audit trail (F9) and the ceiling-compliance proof (F10). Proven end-to-end through the gateway in the compose smoke.

**Architecture:** Spec §2/§8, decisions D-008 (nginx: config-only, routes + limit_req + static), D-009 (Vite+React SPA served as statics). The gateway is the ONLY container exposing a host port for real use (existing per-service host ports 8001–8006 stay for the smoke/debug). App containers are on the default compose network reachable by service name (only their `-dapr` sidecars use `network_mode`), so nginx proxies to `http://intake-api:8000` etc.

**Tech Stack:** nginx (config only) · Vite + React 18 + TypeScript · multi-stage Docker build (node builds the SPA → nginx serves it). No new Python.

## Global Constraints

- The gateway is config-only — zero gateway application code (D-008). All routing/rate-limit/static in `gateway/nginx.conf`.
- Single external entry point (M6): the UI talks ONLY to `/api/*` on the gateway, never to a service host port directly. Rate limiting via `limit_req` on the `/api/` locations.
- The one sync service-to-service call (intake→audit, M5) is NOT routed through nginx (it's Dapr invoke, sidecar-to-sidecar) — the gateway's `/api/audit/*` is a SEPARATE browser-facing route to audit-svc, don't conflate them.
- SPA routing: unknown non-`/api` paths fall back to `index.html` (client-side routing).
- Field-casing caveat (Phase 06 final review): audit trail entries are snake_case (`event_type`, `occurred_at`), notification objects are camelCase (`targetChannels`, `smsSegments`) — the UI must read each as delivered.
- Branch `feature/gateway-ui` off `main`; conventional commits; controller pushes per task; PR at end. Baseline: **358 passed** (Python; the UI adds no pytest). CI's `docker compose build` is the UI's build gate.
- Money is displayed as dollars (cents/100) in the UI; never recompute logic client-side — the UI only renders what the API returns.

### Task 1: The React SPA (submit, status, queue, dashboard, thresholds, trail, F10)

**Files:**
- Create under `ui/`: `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`, `src/main.tsx`, `src/App.tsx`, `src/api.ts` (typed fetch wrappers over `/api/*`), `src/components/*` (Submit, StatusView, ApproverQueue, Dashboard, Thresholds, Compliance), `src/styles.css`
- `.gitignore` additions: `ui/node_modules/`, `ui/dist/` (already covered by root `node_modules/`/`ui/dist/` — verify).

**Interfaces (the API surface the UI consumes, all via the gateway `/api` base):**
- Submit: `POST /api/invoices` (JSON invoice) → `{trackingId, correlationId, status}`.
- Status: `GET /api/invoices/{id}` → view; `GET /api/invoices/{id}?trail=true` → view + `trail: [...]` (F9).
- Resubmit (send-back, F5): `PUT /api/invoices/{id}` (JSON invoice).
- Dashboard (F8): `GET /api/dashboard` → counters.
- Approver queue (F4): `GET /api/approvals/queue` → `{items: [...]}`; verdict (F5): `POST /api/approvals/{id}/verdict` `{verdict, approver_id, comment}`.
- Thresholds (F7): `GET /api/config/thresholds`, `PUT /api/config/thresholds`.
- Ceiling compliance (F10): `GET /api/audit/ceiling-compliance`.

**UI structure (single SPA, tab/nav between views — keep it clean and demo-legible, not flashy):**
- **Submit** — a form pre-fillable from the shipped fixtures (a dropdown of INV-1001…INV-1019 that loads the fixture JSON into the form) plus free editing; on submit, show the tracking id and link to its status.
- **Status** — enter/track an id; show status, route, plain-language reasoning, decidedBy, timestamps; a "Show audit trail" toggle that calls `?trail=true` and renders the ordered event timeline (F9); if status is `needs_info`, offer a resubmit action (F5).
- **Approver queue** (F4/F5) — list escalated items with the agent's recommendation, confidence, cited rules, reasoning, amount; each row has approve / reject / send-back buttons that POST the verdict and refresh.
- **Dashboard** (F8) — the counters: submitted, auto vs human decisions, paid counts, money auto- vs human-approved (render cents as dollars).
- **Thresholds** (F7) — show current thresholds; an admin form to PUT new values (no redeploy).
- **Compliance** (F10) — call ceiling-compliance; show "N auto-approvals checked, 0 violations ✓" as the auditor proof, red if any violation.

### Task 2: nginx gateway + end-to-end smoke through it

**Files:**
- Create: `gateway/nginx.conf`, `gateway/Dockerfile` (multi-stage: `node:20-alpine` builds `ui/` → `nginx:1.27-alpine` serves `dist/` + the conf)
- Modify: `docker-compose.yml` (add `gateway` service, port `8080:80`, depends_on the app services healthy), `scripts/smoke-compose.sh`

**`nginx.conf` (the whole gateway — config only):**
```nginx
worker_processes auto;
events { worker_connections 1024; }
http {
  include /etc/nginx/mime.types;
  default_type application/octet-stream;
  sendfile on;

  # M6 rate limiting: per-client-IP zone, applied to /api/.
  limit_req_zone $binary_remote_addr zone=api:10m rate=20r/s;

  upstream intake       { server intake-api:8000; }
  upstream decision     { server decision-svc:8000; }
  upstream approval     { server approval-svc:8000; }
  upstream payment      { server payment-svc:8000; }
  upstream audit        { server audit-svc:8000; }
  upstream notification { server notification-svc:8000; }

  server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    # --- API routes (single external entry point, M6) ---
    location /api/invoices   { limit_req zone=api burst=20 nodelay; proxy_pass http://intake; }
    location /api/dashboard  { limit_req zone=api burst=20 nodelay; proxy_pass http://intake; }
    location /api/config     { limit_req zone=api burst=20 nodelay; proxy_pass http://decision; }
    location /api/approvals  { limit_req zone=api burst=20 nodelay; proxy_pass http://approval; }
    location /api/budgets    { limit_req zone=api burst=20 nodelay; proxy_pass http://payment; }
    # audit + notification aren't /api-prefixed on their services -> rewrite.
    location /api/audit/ {
      limit_req zone=api burst=20 nodelay;
      rewrite ^/api/audit/(.*)$ /$1 break;
      proxy_pass http://audit;
    }
    location /api/notifications {
      limit_req zone=api burst=20 nodelay;
      rewrite ^/api/notifications$ /notifications break;
      proxy_pass http://notification;
    }

    # --- SPA static + client-side routing fallback (M7) ---
    location / { try_files $uri $uri/ /index.html; }
  }
}
```
(Note: `proxy_pass http://intake` with a trailing-slash-free location preserves the full `/api/invoices/...` path to intake, which already serves under `/api` — correct. Verify each service's real prefix: intake `/api/invoices|/api/dashboard`, decision `/api/config`, approval `/api/approvals`, payment `/api/budgets`; audit `/trail|/audit`, notification `/notifications` → hence the rewrites.)

**`gateway/Dockerfile`:**
```dockerfile
FROM node:20-alpine AS build
WORKDIR /ui
COPY ui/package.json ui/package-lock.json* ./
RUN npm ci || npm install
COPY ui/ ./
# the fixtures the submit dropdown loads
COPY sample-invoices.json ./public/sample-invoices.json
RUN npm run build

FROM nginx:1.27-alpine
COPY gateway/nginx.conf /etc/nginx/nginx.conf
COPY --from=build /ui/dist /usr/share/nginx/html
EXPOSE 80
```

```bash
  || { echo "FAIL: audit via gateway (rewrite)"; exit 1; }

  || { echo "FAIL: notifications via gateway (rewrite)"; exit 1; }

echo "--- gateway rate limiting (M6) ---"
RL=0
for i in $(seq 1 60); do
  code=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/dashboard)
  [ "$code" = "503" ] && RL=1 && break
done
[ "$RL" = "1" ] || { echo "FAIL: rate limit never triggered (expected a 503 under burst)"; exit 1; }
echo "RATE LIMIT (limit_req returned 503 under burst): OK"
```
