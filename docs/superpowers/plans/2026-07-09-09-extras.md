# Phase 09 — Extras Implementation Plan (N6 · N1 · N5 · B1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The four planned extras from spec §11, built strictly in this order after the must-haves went green: **N6** tests-across-layers + D5 e2e wired into CI, **N1** self-signed JWT auth with roles, **N5** local RAG (per-rule chunking + BM25) over the policy in decision-svc, **B1** an automated eval harness that scores the labeled fixtures and writes a committed `eval/REPORT.md`.

**Architecture:** Extend the existing monorepo without new heavy containers. Auth is a shared `afcommon.auth` module (HS256 self-signed JWT) enforced by a FastAPI dependency in each service. RAG is a pure-Python retriever in decision-svc that produces the `policy_rules` string the frozen `DecisionAgent.evaluate(invoice, policy_rules)` port already consumes — no port change. The eval harness runs the real `DecisionPipeline` in-process with the stub adapter (no compose), reusing the shipped fixtures' `expected.route` labels.

**Tech Stack:** Python 3.12 · FastAPI · PyJWT · a hand-rolled BM25 (no new dependency beyond PyJWT) · pytest · GitHub Actions · React/TS (UI login). No new services.

## Global Constraints

- **Order is fixed:** N6 → N1 → N5 → B1. Each feature's tasks complete and its tests pass before the next begins. Baseline before this phase: **358 passed**; every task keeps the full suite green (`pytest -q`) and `ruff check .` clean.
- **Import guards (CI, already enforced):** no `from libs.` / `import libs.`; service `src/` modules use **relative** imports only (never `from services.X.src…`). New code obeys both.
- **Money is integer cents** everywhere; never float math on money.
- **N1 must not break the graded D5 `make verify` or `scripts/smoke-compose.sh`.** Auth is gated by an `AUTH_ENABLED` env var (default **true** in `docker-compose.yml`). When on, `verify.sh` and `smoke-compose.sh` obtain a token via `POST /api/auth/login` and send it as `Authorization: Bearer <jwt>` on every protected call — this both keeps the graded run green AND proves role enforcement end-to-end. The JWT signing secret comes from the Dapr secrets file (`dapr/secrets.json`, key `jwt-signing-secret`), never hard-coded.
- **N5 fallback:** RAG is gated by `RAG_ENABLED` (default **true**). When false, decision-svc passes the full `policy.md` to the agent exactly as today (current behavior preserved). RAG never changes the deterministic router or the stub agent's decision — it only narrows the prompt for the LLM path and records which `rule_id`s were retrieved.
- **B1 in CI uses the stub adapter only** (no LLM). The committed `eval/REPORT.md` is regenerated from a manual real-model run by Daniel; CI asserts the stub sweep stays safe (no M12 ceiling breach, no route regressions vs the labeled set for the deterministic gates).
- Branch `feature/extras` off `main`; conventional commits; controller pushes per task; one PR at the end. CI (ruff + pytest + compose build + the new e2e + eval jobs) must be green before merge.

## FEATURE N5 — RAG over the policy (per-rule chunking + local BM25)

At decision-svc startup, chunk `policy.md` one chunk per `rule_id`. Retrieval = category filter (a meals invoice always gets `MEAL-*` + `GLOBAL-*`) + BM25 over line-item descriptions and notes. Only top-k rules enter the agent prompt; retrieved `rule_id`s are logged onto the decision event. Falls back to full policy when `RAG_ENABLED=false`.

### Task N5.1: The retriever (`retrieval.py`) — chunking + BM25 + category filter

**Files:**
- Create: `services/decision/src/retrieval.py`
- Create: `services/decision/tests/test_retrieval.py`

**Interfaces (Produces):**
- `chunk_policy(policy_md: str) -> dict[str, str]` — maps each `rule_id` (e.g. `MEAL-01`) to its rule text (the table-row cell). Parse the markdown tables; a chunk is the `rule_id` + its rule sentence.
- `CATEGORY_PREFIXES: dict[str, list[str]]` — `{"meals": ["MEAL", "GLOBAL"], "travel": ["TRAVEL", "GLOBAL"], "saas"/"software": ["SAAS", "GLOBAL"], "hardware": ["HW", "GLOBAL"], ...}`. Read `policy.md` for the actual categories/prefixes; `GLOBAL` always included.
- `class PolicyRetriever:` built from `chunk_policy(...)`; `retrieve(invoice: dict, k: int = 5) -> list[str]` returns the selected `rule_id`s: always the category-filtered rule ids, then BM25-rank all chunks by the query text (line-item descriptions + notes + category) and union the top-k. `render(rule_ids: list[str]) -> str` returns a policy-rules string (the chunks joined) to feed the agent.
- BM25: implement a small, dependency-free BM25 (`k1=1.5`, `b=0.75`) over whitespace-lowercased tokens. No embeddings, no network.

Load the real `policy.md` via the repo-root finder used elsewhere (`deps._find_repo_file` pattern — read `deps.py`).
